# Agentic Service Desk — 구현 로드맵

- 문서 목적: 설계(M-003)를 **만들 순서**로 옮긴다. 각 묶음의 목표·산출물·완료 조건·의존을 정한다. M-004 산출물.
- 범위: 구현 순서 원칙 · 8개 묶음(WBS-4.1~4.8) · 완료 조건 · 위험
- 대상 독자: AI agent, 저장소 maintainer
- 상태: draft
- 최종 수정일: 2026-08-28
- 관련 문서: [설계](./architecture/README.md), [요구사항](./REQUIREMENTS.md), [컨셉 §1.5](../ai-workflow/wiki/concepts/agentic-service-desk-concept.md#s1-5-rollout)

## §1 순서를 정하는 원칙  {#s1-principles}

| # | 원칙 | 근거 |
|---|---|---|
| 1 | **도입 단계(S0~S5)를 따른다** | D49. 대외 노출은 늦게, 내부 축적은 일찍 |
| 2 | **기반은 한 번에 다 만들지 않는다** | 어댑터 표면 일곱도 필요한 단계에 하나씩 는다 |
| 3 | **대시보드는 단계마다 조금씩** | FR-59. 켜지지 않은 기능의 대기열은 만들지 않는다 |
| 4 | **핵심 경로를 먼저, 운영 부가는 뒤에** | 1인 겸업(CO-7)이므로 동시에 벌리지 않는다 |

> **활성화 순서와 개발 순서는 다르다**(§1.5.4). 다만 1인이 한 번에 다 만들 수 없으므로
> **여기서는 둘을 같이 간다.** 앞 단계를 켜서 돌려 보고 다음을 만든다.

## §2 묶음 지도  {#s2-map}

| 묶음 | 단계 | 무엇을 만드는가 | 대외 노출 |
|---|---|---|---|
| **4.1 기반** | S0 이전 | 골격 · 어댑터(읽기) · LLM 게이트웨이 · 저장소 | 없음 |
| **4.2 수집과 지식베이스** | S0 | 수집 · 필터 · Ingest · Lint · 대시보드 최소 | **없음** |
| **4.3 수동 등록과 티켓** | S1 | 티켓 도메인 · 종결 기록 · 등록 화면 · 승격 A | **없음** |
| **4.4 답변 초안** | S2 | 검색 · 파이프라인 1~4단계 · 검수 | **없음** |
| **4.5 게재와 추적** | S3 | 게재 · 답변 이력 · 추적 · 승격 B · 정정 | **시작** |
| **4.6 가이드** | S4 | 콘텐츠 타입 · 가이드 · 문서 면 게재 | 넓어짐 |
| **4.7 FAQ·칼럼·뉴스레터** | S5 | 나머지 콘텐츠 타입 | 최대 |
| **4.8 운영 부가** | S3 이후 병행 | 국면 판정 · 알림 · 보존 만료 · 표본 재검증 | — |

**4.1~4.4 는 아무것도 내보내지 않는다.** 여기까지가 절반이며, 그 구간에서 지식과
답변의 품질을 먼저 확인한다.

## §3 묶음별 완료 조건  {#s3-exit}

각 묶음은 **다음 묶음으로 넘어갈 조건**을 갖는다. §1.5.4 대로 **앞 단계의 대기열이
밀려 있으면 다음을 켜지 않는다** — 만드는 것은 계속하되 **켜지 않는다.**

| 묶음 | 완료 조건 |
|---|---|
| 4.1 | 배치·온라인 두 프로세스가 뜨고, 어댑터가 모 시스템에서 질문·답변·후속·해결 표시를 읽어 온다 |
| 4.2 | 지식 항목이 쌓이고 **Lint 가 안정**된다 (모순 미해결 0, 깨진 링크 0) |
| 4.3 | 수동 등록 → 종결 → **지식 승격(A 경로)이 실제로 돈다** |
| 4.4 | 초안 품질이 만족스럽다 — **검수 반려율이 낮다** |
| 4.5 | 명시적 해결이 쌓이고 **커버리지가 오른다** |
| 4.6 | QnA 가 쌓여 **반복 패턴이 보인다** (2국면 진입, §1.3.3) |
| 4.7 | — |
| 4.8 | 국면 전환 제안이 뜨고, 위험 대기열 알림이 도달한다 |

## §4 의존  {#s4-dependencies}

```
 4.1 기반
  ├─▶ 4.2 수집·지식베이스 ──┬─▶ 4.3 티켓 ──┐
  │                        │              ├─▶ 4.5 게재·추적 ──┬─▶ 4.6 가이드 ─▶ 4.7 콘텐츠
  │                        └─▶ 4.4 초안 ──┘                  └─▶ 4.8 운영 부가
  └─────────────────────────────────────────────────────────────┘
```

- **4.3 과 4.4 는 서로 독립**이다. 둘 다 4.2 를 필요로 하고 4.5 가 둘을 필요로 한다
- 4.8 은 4.5 이후 **언제든** 붙일 수 있다 — 핵심 경로를 막지 않는다
- 4.6 → 4.7 은 순서가 있다. 가이드가 FAQ 보다 먼저다(D50)

## §5 위험  {#s5-risks}

| # | 위험 | 어디서 드러나는가 | 대응 |
|---|---|---|---|
| 1 | **4.2 에서 지식 품질이 안 나온다** | Lint 모순·stale 이 안 잡히거나 항목이 쓸모없다 | 입도를 더 굵게(ADR-003). 그래도 안 되면 ingest 프롬프트를 손본다 |
| 2 | **4.4 검색이 근거를 못 찾는다** | 대부분의 질문이 티켓으로 간다 | 1국면에는 **정상**(D14). 표현 사전이 비어 있어서다. 2국면에도 낮으면 ADR-004 를 다시 본다 |
| 3 | **커밋 위생이 나빠 히스토리가 쓸모없다** (O41) | 4.2 에서 "왜"가 안 뽑힌다 | 운영자=개발자이므로 **앞으로의 커밋을 고치면 된다**(§8.6.2). 과거분은 포기 |
| 4 | **1인이 4.5 이후 대기열을 못 따라간다** | 승인 소요 시간·무수정 승인 비율(§5.6.6) | 다음 묶음을 **켜지 않는다.** 만드는 것과 켜는 것을 분리한다 |
| 5 | **GPU 한 대에 병목** | 배치 중 답변 지연 | ADR-005 의 양보 규칙으로 시작. 부족하면 그때 인스턴스를 나눈다 |

## §6 이 로드맵이 정하지 않는 것  {#s6-out}

- **일정** — 1인 겸업이므로 기간을 약속하지 않는다. 순서와 조건만 정한다
- **각 묶음 내부의 작업 분해** — 착수 시점에 backlog task 로 쪼갠다
- **실데이터가 필요한 임계값 9건** — 4.5 를 켜서 돌려 봐야 정해진다 (컨셉 §0.4)
