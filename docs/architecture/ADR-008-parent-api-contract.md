# ADR-008 — 모 시스템 API 계약은 우리가 정의한다

- 상태: accepted
- 결정일: 2026-08-28
- 관련: [ADR-006](./ADR-006-source-sync.md), 요구사항 §2 (XR-1~7)

## 맥락

일곱 표면(XR-1~7)을 요구했지만 **모 시스템에 아직 그 API 가 없다.** 명세를 받아 올
곳이 없다는 뜻이다.

그런데 컨셉은 이미 답을 갖고 있었다 — **운영자가 곧 모 시스템 개발자이므로**(D30)
"없는 것은 요청 대상이 아니라 **만들 항목**"이다(§9.8.1). 협상할 상대가 없는 것이
아니라, **우리가 쓰면 된다.**

## 결정

**계약을 이쪽에서 정의하고, mock 을 그 실행 가능한 명세로 삼는다.**

| 산출물 | 역할 |
|---|---|
| `adapters/contract.py` | 일곱 표면이 주고받는 **자료 형태** |
| `adapters/mock.py` | 계약을 만족하는 **인메모리 구현**. 개발·테스트가 이 위에서 돈다 |
| `adapters/http.py` | 실제 연동 자리. 모 시스템에 API 가 생기면 채운다 |

### 왜 mock 을 제대로 만드는가  {#why-real-mock}

빈 값을 돌려주는 스텁으로 두면 4.2~4.5 를 **아무것도 검증하지 못한 채** 만들게 된다.
그래서 mock 은 **시나리오를 담는다** — 답변 없는 질문, 봇이 답하고 명시적 해결된 것,
봇이 답했으나 미해결인 것, 사람이 답한 것, 후속이 달린 것.

이 다섯이 §5.3 되먹임 차단의 **모든 분기**를 덮는다. 필터를 실제로 시험할 수 있다.

> **문서로만 쓴 스키마는 어긋난다.** mock 이 프로토콜을 만족하면 그 자체가 검증이고,
> 나중에 HTTP 구현이 같은 프로토콜을 만족하면 갈아 끼우기만 하면 된다.

### 계약이 곧 모 시스템에 만들 API 의 명세다  {#contract-as-spec}

여기서 정한 형태가 **모 시스템 쪽 작업 지시서**가 된다. 순서가 뒤집힌 것처럼 보이지만
그렇지 않다 — 표면 목록은 이미 컨셉이 **필요에서** 도출했고(D34), 여기서는 그 형태를
구체화할 뿐이다.

## 계약 정정 — 콘텐츠 게재는 두 연산이다  {#two-content-ops}

컨셉의 프로토콜은 `publish_content(kind, path, body)` 하나였다. **나눈다.**

| 연산 | 대상 | 성격 |
|---|---|---|
| `upsert_document(path, ...)` | 문서 면 | 살아있는 문서 — 없으면 만들고 있으면 갱신 |
| `create_publication(...)` | 발행 면 | 발행물 — 새 회차 |

D46 이 "타입이 넷이어도 **자리는 둘이고 연산도 둘**"이라고 했는데, 하나의 메서드에
`kind` 를 넘기면 그 둘이 코드에서 흐려진다. **성격이 다르면 메서드도 다르다** —
upsert 는 멱등이고 create 는 아니다.

## 대안과 기각 이유

| 대안 | 기각 이유 |
|---|---|
| API 가 생길 때까지 기다린다 | 4.2~4.5 를 시작조차 못 한다. 지식 구축은 QnA 없이도 가능하다 |
| 빈 스텁만 두고 진행 | 아무것도 검증되지 않는다. 나중에 실제 연동에서 한꺼번에 터진다 |
| 모 시스템 DB 직결로 우회 | ADR-002 가 이미 기각했다. 스키마 변경에 직격탄을 맞는다 |
| 계약을 문서로만 정의 | 코드와 어긋난다. mock 이 프로토콜을 만족하는 것이 곧 검증이다 |

## 귀결

- **mock 이 프로덕션에서 도는 사고**를 막아야 한다 → 설정에서 명시적으로 고르게 하고,
  선택되면 기동 시 경고를 남긴다
- 실제 API 가 생기면 계약이 **바뀔 수 있다.** 그때 mock 과 HTTP 구현이 함께 움직인다 —
  프로토콜 하나를 둘이 만족하므로 어긋나면 테스트가 잡는다
- 이 ADR 은 **연결 단계에서 다시 열린다.** 그때 실제 모 시스템의 제약(인증·페이지네이션·
  응답 형태)이 계약을 조정할 것이다
