# ADR-002 — 저장소와 그 사이의 무결성

- 상태: accepted
- 결정일: 2026-08-28
- 해소: O33 (저장소 간 일관성) · O46 (버전 단위)
- 관련: [ADR-003](./ADR-003-knowledge-granularity.md)

## 맥락

저장소가 둘로 갈리는 것은 컨셉에서 확정됐다(D12) — 지식은 파일 + 버전 관리,
운영 데이터는 데이터베이스. **남은 것은 DB 제품 선택과 두 저장소를 잇는 출처
링크의 무결성**이다.

## 결정 1 — 운영 DB 는 SQLite  {#db}

| | SQLite | PostgreSQL |
|---|---|---|
| 운영 부담 | **없다** — 파일 하나 | 서버 프로세스 하나가 는다 |
| 백업 | **파일 복사** | 덤프 절차 |
| 동시 쓰기 | 낮음 (WAL 로 완화) | 강함 |
| 이 시스템의 부하 | 질문 일 단위 소수(§1.3.1), 쓰기 주체는 온라인·배치 둘 | 과잉 |

**SQLite(WAL 모드)를 택한다.** 1인 겸업 환경에서 **DB 서버 하나가 늘어나는 것이 곧
운영 부담**이고, 이 시스템의 부하는 그 부담을 정당화하지 않는다.

이용자가 7,000명으로 늘어도 QnA 는 일 단위 수십 건이다. 규모가 실제로 커지면
PostgreSQL 로 옮기되, **지금 도입할 이유가 없다.**

## 결정 2 — 지식 항목은 경로와 별개의 불변 id 를 갖는다  {#stable-id}

여기서 차용한 두 컨셉이 부딪힌다.

| | OKF | 우리 요구 |
|---|---|---|
| 개념 ID | **파일 경로**(확장자 제외) | 답변 이력이 지식 항목을 **안정적으로** 가리켜야 한다(D20) |

파일을 옮기거나 이름을 바꾸면 경로 ID 가 바뀌고, **답변 이력의 근거 링크가 끊긴다.**
지식 항목은 입도 조정(ADR-003)으로 실제로 이동한다.

> **결정**: frontmatter 에 **불변 `id`** 를 둔다. OKF 소비자에게는 경로가 ID 로 보이고,
> 내부 참조는 `id` 를 쓴다. 파일이 이동해도 링크가 살아남는다.

OKF 는 미지의 frontmatter 키를 거부하지 않으므로(consumer MUST NOT reject) 형식
준수가 깨지지 않는다.

## 결정 3 — 근거 버전은 커밋 해시로 고정한다  {#version-pin}

O30 이 git 을 확정했으므로 **버전 = 커밋 해시**다. 답변 이력은
`(지식 항목 id, 커밋 해시)` 쌍으로 근거를 고정한다(D20).

항목 단위 해시를 따로 두지 않는다 — 커밋 해시로 그 시점의 파일 내용을 재현할 수 있고,
별도 해시는 관리 대상만 늘린다.

## 결정 4 — 무결성은 Lint 가 지킨다  {#integrity}

두 저장소를 잇는 것은 출처인데, **그 링크를 강제할 외래키가 없다**(파일과 DB 사이라서).

> **Lint 검사에 두 항목을 더한다.**
> - 답변 이력이 가리키는 **지식 항목 id 가 실재하는가**
> - 지식 항목의 출처 커밋이 **저장소에 실재하는가**

깨진 링크는 삭제하지 않고 **Q5(정정 후보)로 올린다** — 링크가 끊겼다는 것은 근거를
알 수 없게 됐다는 뜻이고, 그 답변은 재검토 대상이다.

## 대안과 기각 이유

| 대안 | 기각 이유 |
|---|---|
| 처음부터 PostgreSQL | 1인 운영에 서버 하나가 는다. 부하가 정당화하지 않는다 |
| 지식도 DB 에 | D12 를 뒤집는다. llm-wiki 운영 모델(1 커밋 = 1 ingest)이 성립하지 않는다 |
| 경로를 ID 로 그대로 사용 | 파일 이동 시 답변 이력의 근거 링크가 끊긴다 |
| 항목 단위 콘텐츠 해시 | 커밋 해시로 충분하다. 관리 대상만 는다 |

## 귀결

- 백업이 **파일 두 벌**(git 저장소 + SQLite 파일)로 끝난다 — 1인 운영에 큰 이점
- 동시 쓰기 한계가 있다. 온라인·배치가 같은 DB 를 쓰므로 **쓰기를 짧게** 유지해야 한다
- 무결성이 **사후 검사(Lint)** 로 지켜진다. 즉시 강제되지 않으므로 검사 주기가 중요하다
