# ADR-003 — 지식 항목의 입도

- 상태: accepted
- 결정일: 2026-08-28
- 해소: O11
- 관련: [ADR-002](./ADR-002-storage.md), [ADR-004](./ADR-004-retrieval.md)

## 맥락

컨셉이 걸어 둔 제약이 셋이다.

1. **언어 중립 단위**여야 한다 — 다언어 코드베이스라 언어별 파서를 두지 않는다(§4)
2. **국면에 따라 바뀌는 값**이다 — 초기엔 굵게, 코드가 안정된 뒤 세분화(§1.3.2)
3. 코드 규모는 **5만~50만 줄**(§1.1)

## 결정

**개념 단위로 만든다. 파일이나 함수를 단위로 삼지 않는다.**

| 후보 | 판단 |
|---|---|
| 파일 단위 | **아니다.** 수천 개가 되고, 무엇보다 **파일이 개념과 1:1 이 아니다** |
| 함수·클래스 단위 | **아니다.** 언어별 파싱이 필요해 제약 1 을 깬다 |
| **개념 단위** | **채택.** "결재 한도가 결정되는 규칙", "알림이 발송되는 조건" 같은 단위 |

개념 단위의 항목은 **근거가 여러 파일·여러 커밋에 걸칠 수 있다.** 출처는 단수가
아니라 목록이다.

### 질문이 입도를 정한다  {#demand-driven}

제약 2("국면에 따라 바뀐다")를 어떻게 실행할지가 남는다. **미리 세분화하지 않는다.**

> 굵은 항목으로 시작하고, **질문이 특정 지점을 반복해 찌르면 그 부분만 쪼갠다.**

근거는 §1.3.2 다 — 코드 변동이 큰 시기에 정교하게 지어 두면 곧 stale 이 되어 투자가
회수되지 않는다. 그리고 **어디를 세분화해야 하는지는 질문이 알려준다.** 아무도 묻지
않는 영역을 잘게 나누는 것은 낭비다.

세분화 트리거는 대시보드의 **지식 공백(Q8)** 과 반복 질문 탐지가 이미 제공한다 —
새 장치가 필요 없다.

## 대안과 기각 이유

| 대안 | 기각 이유 |
|---|---|
| 처음부터 세밀하게 | 코드 변동기에 stale 폭증. §1.3.2 위반 |
| 정적 분석으로 자동 분할 | 언어별 도구가 필요해 제약 1 을 깬다. §1.2 가 에이전트 기반을 택한 이유가 사라진다 |
| 고정 입도 | 제약 2 위반. 국면에 따라 바뀌어야 한다 |

## 귀결

- 항목 수가 **수백~수천** 규모로 유지된다 → 검색 설계가 단순해진다(ADR-004)
- 항목이 **실제로 이동·분할된다** → ADR-002 의 불변 `id` 가 필수가 된다
- 세분화가 **수요를 따라가므로 뒤늦다.** 새 영역의 첫 질문은 굵은 항목으로 답해지고
  정밀도가 떨어질 수 있다 — 이는 §1.3.3 의 국면 역행 신호로 드러난다
