# ADR-005 — 로컬 LLM 구성과 자원 배분

- 상태: accepted
- 결정일: 2026-08-28
- 해소: O9 (모델 구성) · O32 (자원 배분)
- 관련: [ADR-001](./ADR-001-stack.md), [ADR-004](./ADR-004-retrieval.md)

## 맥락

**GPU 서버가 있다**(§1.1). 이 사실이 컨셉이 열어 둔 두 미결을 크게 좁힌다.

에이전트는 셋이고 요구가 서로 다르다.

| 에이전트 | 경로 | 우선하는 것 |
|---|---|---|
| 구축 (ingest) | 배치 | 정확도 · 처리량 |
| 응답 (답변·콘텐츠 생성) | 온라인 | **지연** |
| 검수 | 온라인 | 정확도 — **생성과 분리되어야 한다**(D21) |

## 결정 1 — 하나의 모델 인스턴스를 공유한다  {#shared}

**별도 인스턴스를 띄우지 않는다.**

질문 절대량이 적어(§1.3.1) 온라인 부하가 낮다. 에이전트마다 인스턴스를 두면
**GPU 가 대부분의 시간을 놀게** 되고, 1인 겸업 환경에 관리 대상만 는다.

## 결정 2 — 온라인이 배치에 우선한다  {#priority}

O32 가 걱정한 것은 "대규모 ingest 중 답변이 굶는" 상황이다.

> **LLM 게이트웨이**를 두고 요청에 우선순위를 준다. 온라인 요청이 오면 배치는
> **청크 경계에서 양보**한다.

##### 구현하며 드러난 것 — 우선순위 큐가 아니라 프로세스 간 신호다  {#cross-process}

이 결정을 쓸 때는 게이트웨이 하나가 두 종류의 요청을 받아 줄 세우는 그림이었다.
그런데 **온라인과 배치는 다른 프로세스**다(NFR-6) — 메모리를 공유하지 않으므로
**한 프로세스 안의 우선순위 큐로는 조정되지 않는다.**

실제 형태는 **양보 신호**다. 온라인이 LLM 을 쓰는 동안 공유 표시를 남기고, 배치는
청크 경계에서 그것을 확인해 기다린다. 표시는 파일로 둔다 — 1인 운영에서
**조정용 서버를 하나 더 띄우지 않기 위해서**다(CO-7).

두 가지 안전장치가 붙는다.
- **낡은 표시는 무시한다.** 온라인 프로세스가 죽어 표시를 못 지우면 배치가 영원히
  굶는다
- **양보에 상한을 둔다.** 지식이 안 자라는 것도 실패다(§8.2)

결정의 뜻은 바뀌지 않았다 — 온라인이 먼저이고 배치가 비켜 준다. 다만 **어떻게**가
달라졌다.

배치를 중단 가능하게 만드는 것이 요점이다 — ingest 를 한 덩어리로 돌리지 않고
**항목 단위로 쪼개** 사이사이 양보 지점을 만든다. 중단돼도 다음 주기에 이어서 한다.

이 단순한 규칙으로 충분한 이유는 **충돌 확률 자체가 낮기 때문**이다(§1.3.1).
정교한 스케줄러를 지금 만들 필요가 없다.

## 결정 3 — 검수는 별도 프롬프트·별도 컨텍스트로 돌린다  {#review-isolation}

D21 은 검수를 생성과 분리하라고 요구한다. **별도 모델이 이상적이지만 필수는 아니다.**

> 같은 모델을 쓰되 **검수 요청에는 초안과 근거 원문만 넣는다.** 질문 의도·생성
> 과정·이전 대화를 전달하지 않는다.

분리의 본질은 모델이 다른 것이 아니라 **보는 것이 다른 것**이다(§5.5.2). 컨텍스트를
끊는 것만으로 "그럴 만했다"로 기우는 경향이 줄어든다.

GPU 여유가 확인되면 검수용 모델을 따로 두는 쪽이 낫다 — 다만 그것은 개선이지
전제가 아니다.

## 결정 4 — 모델을 교체 가능하게 감싼다  {#abstraction}

하드웨어와 모델은 바뀐다. **호출부가 특정 런타임에 묶이지 않게** 한 겹을 둔다.

임베딩(ADR-004)도 같은 게이트웨이를 지난다 — 임베딩 모델 역시 **로컬이어야 한다**
(NFR-1: 지식 항목은 소스코드 파생이므로 외부 전송이 곧 반출이다).

## 대안과 기각 이유

| 대안 | 기각 이유 |
|---|---|
| 에이전트별 인스턴스 | 질문량이 적어 GPU 가 논다. 관리 대상만 는다 |
| 시간대 분리 (배치는 야간만) | 코드 변경 직후 지식이 낡은 채 낮을 보낸다. stale 전파가 하루 늦는다 |
| 외부 LLM API 병용 | **NFR-1 위반.** 소스코드 파생 내용의 반출이다 |
| 배치 무중단 우선 | 답변 지연이 곧 채택 실패(W4)로 이어진다. §8.6.3 이 이미 경고했다 |

## 귀결

- GPU 한 대에 **온라인·배치·임베딩이 모두 얹힌다.** 병목이 생기면 가장 먼저 드러날 곳이다
- 배치가 **자주 중단·재개**되므로 ingest 는 **중단 지점을 기억**해야 한다
- 모델 교체 시 **지식 항목의 문체·구조가 달라질 수 있다.** 기존 항목과 새 항목이
  어긋나면 Lint 가 모순으로 잡을 수 있으므로, 교체는 국면 전환처럼 다뤄야 한다
