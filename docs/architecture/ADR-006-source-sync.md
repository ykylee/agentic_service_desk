# ADR-006 — 소스 보유 형태와 동기화

- 상태: accepted
- 결정일: 2026-08-28
- 해소: O10
- 관련: [ADR-002](./ADR-002-storage.md), [ADR-005](./ADR-005-llm-runtime.md)

## 맥락

원천은 **코드 + 저장소 히스토리**다(D16). 히스토리가 "왜 그렇게 정했는가"의 1차
출처이므로(§2.2.1), 코드만 가져오는 형태는 쓸 수 없다.

운영자가 곧 모 시스템 개발자이므로(D30) 저장소 접근에 제약이 없다.

## 결정

**읽기 전용 전체 클론을 두고 주기적으로 fetch 한다.**

| 항목 | 값 | 이유 |
|---|---|---|
| 형태 | **전체 클론** (shallow 아님) | 히스토리가 원천이다. `--depth` 를 주면 커밋 메시지가 잘린다 |
| 권한 | **읽기 전용** | CO-1 — 소스코드에 쓰지 않는다. 자격증명 자체를 읽기 전용으로 |
| 갱신 | 주기적 `fetch` | 새 커밋이 ingest 트리거다 |
| 부분 수집 | 하지 않는다 | 중규모(5만~50만 줄)라 전체를 둬도 부담이 없다 |

### QnA 는 폴링으로 읽는다  {#qna-polling}

소스는 git 이지만 QnA 는 API 다(D34). **분 단위 폴링**(NFR-7)으로 신규 질문·후속·
해결 표시를 가져온다.

주기를 짧게 두는 이유는 §9.8.2 대로다 — **폴링 주기가 답변 지연에 그대로 더해지고**,
1인 겸업의 검수 지연(§8.6.3)과 겹치면 두 겹이 된다.

### 증분의 단위는 커밋이다  {#incremental}

전체 ingest 는 최초 1회뿐이고(FR-2), 이후는 **마지막 처리 커밋 이후의 변경 범위**만
다시 읽는다. 마지막 처리 지점을 운영 DB 에 기록한다.

ADR-005 가 배치를 중단 가능하게 만들었으므로, **중단 지점도 같은 자리에 남긴다.**

## 대안과 기각 이유

| 대안 | 기각 이유 |
|---|---|
| shallow clone | 히스토리가 잘려 §2.2.1 의 원천이 사라진다 |
| 부분 클론 (sparse) | 중규모라 이득이 없고, 어느 경로가 필요한지 미리 알 수 없다 |
| 웹훅으로 push 받기 | 모 시스템에 표면이 하나 더 는다. 폴링으로 충분하다 |
| API 로 파일만 읽기 | 히스토리를 못 얻는다 |

## 귀결

- 디스크에 **모 시스템 저장소 사본**이 상주한다 — 보안 경계 안에 두어야 한다
- fetch 주기가 곧 **stale 감지 지연**이다. 코드가 바뀌어도 다음 fetch 까지는 모른다
- 저장소가 커지면 클론 크기가 문제가 될 수 있다. 지금 규모에서는 아니다
