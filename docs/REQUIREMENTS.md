# Agentic Service Desk — 요구사항

- 문서 목적: 컨셉(v1.0)에서 요구를 끌어내 **검증 가능한 항목**으로 정리한다. M-002 WBS-2.1 산출물.
- 범위: 모 시스템에 대한 요구사항 · 기능 · 비기능 · 제약 · 이 단계에서 정한 정책 · 추적성
- 대상 독자: AI agent, 저장소 maintainer
- 상태: draft
- 최종 수정일: 2026-09-03
- 관련 문서: [컨셉 허브](../ai-workflow/wiki/concepts/agentic-service-desk-concept.md) — **먼저 읽는다**, [미결 쟁점](../ai-workflow/wiki/concepts/open-issues.md)

## §1 이 문서의 규칙  {#s1-rules}

| 규칙 | 내용 |
|---|---|
| **추적성** | 모든 요구사항은 컨셉의 결정(**D**n) 또는 절(**§**n)을 근거로 갖는다. 근거 없는 요구사항은 쓰지 않는다 |
| **검증 가능성** | 각 항목에 *무엇을 보면 충족을 아는가*를 적는다 |
| **단계 배정** | 컨셉 §1.5 의 도입 단계(**S0~S5**)에 배정한다. 우선순위를 따로 매기지 않는 이유는 단계가 이미 순서이기 때문이다 |
| **기술 선택 금지** | 언어·프레임워크·DB·검색 방식은 **M-003 설계**의 몫이다 (§9.1). 여기서는 *무엇이 필요한가*까지만 쓴다 |

식별자는 **XR**(모 시스템에 요구) · **FR**(기능) · **NFR**(비기능) · **CO**(제약) · **PO**(정책)로 나눈다.

## §2 모 시스템에 대한 요구사항 (XR)  {#s2-external}

> **이 절이 가장 먼저 온다.** 컨셉의 전제 2·3·7 이 실은 이 목록의 다른 표현이며,
> **표면이 좁으면 기능이 소리 없이 죽는다**(D34) — 파이프라인은 계속 돌고 지식도 계속
> 자라지만 오답을 섞은 채로. 운영자가 곧 모 시스템 개발자이므로(D30) 이것들은
> 협상 대상이 아니라 **만들 항목**이다.

| ID | 요구 | 방향 | 확인 | 없으면 무엇이 죽는가 | 근거 |
|---|---|---|---|---|---|
| **XR-1** | 질문 목록·상세 조회 | 읽기 | — | 파이프라인 1단계 입력이 없다 | §9.8.1 |
| **XR-2** | 답변 목록 조회 — **작성자 계정 포함** | 읽기 | **확보 (2026-08-28)** | **§5.3 되먹임 차단 전체.** 봇/사람을 가릴 수 없으면 시스템이 자기 답변을 다시 배운다 | D7, 전제 2 |
| **XR-3** | 후속 답글 조회 | 읽기 | 확보 | §6 지속 추적과 파이프라인 재실행 | D9, 전제 3 |
| **XR-4** | **해결 표시 상태** 조회 | 읽기 | 확보 | **명시적 해결 판정**. ingest 자격과 승격이 모두 여기서 나온다 | D8, D35 |
| **XR-5** | 답변 게재 | 쓰기 | — | 파이프라인 5단계 | D6 |
| **XR-6** | 콘텐츠 게재 — 문서 면 **upsert** / 발행 면 **create**. **두 연산이다** (ADR-008) | 쓰기 | — | §7 콘텐츠 전체 | D46, 전제 7 |
| **XR-7** | **답변 수정** — 게재한 답변을 고칠 수 있어야 한다 | 쓰기 | **확보 (2026-08-28)** | **정정 경로(Q5·W3)** | PO-1 |

### §2.1 XR-7 은 컨셉에서 빠져 있던 표면이다  {#s2-1-gap}

컨셉 §9.8.1 은 표면을 여섯으로 적었으나, **정정할 쓰기 수단이 없다.** 시스템은
Q5(정정 후보) 대기열을 두고 W3(게재 후 진실 변화)를 다루기로 했는데, 정작 고칠
방법이 없는 상태였다.

> 요구사항 단계에서 발견된 컨셉의 누락이다. 컨셉 §9.8.1 을 **일곱 표면**으로 정정해야 한다.

### §2.2 XR 이 충족되지 않을 때  {#s2-2-fallback}

| 미충족 표면 | 대안 | 대가 |
|---|---|---|
| XR-2 (작성자 계정) | **없다.** 되먹임 차단이 불가능하므로 **봇 답변을 영구 배제**하는 수밖에 없다 | 지식 성장 경로 B 가 통째로 막힌다 (§6.8.1) |
| XR-4 (해결 표시) | 운영자 확인 종결만 명시적 해결로 인정 | 1인 겸업에게 부담이 몰리고 지식 성장이 느려진다 |
| XR-7 (답변 수정) | 후속 답글로 정정문을 단다 | 원 답변이 틀린 채 남는다. 나중에 읽는 사람은 정정을 못 볼 수 있다 |
| XR-6 (콘텐츠 게재) | S4·S5 를 켜지 않는다 | 답변만 하는 시스템이 된다 |

**XR-2 만이 대안 없는 항목**이었고, **2026-08-28 확인 결과 확보되었다.** 이로써
§5.3 되먹임 차단과 §6.8 의 지식 성장 경로 B 가 성립한다.

XR-7(답변 수정)도 확보되어 PO-1 의 정정 방식을 원안대로 간다 — 후속 답글 대체안은
쓰지 않는다.

> 이 표는 **폐기하지 않고 남긴다.** 모 시스템 API 가 나중에 바뀔 수 있고, 그때
> 무엇이 먼저 무너지는지를 이 표가 알려준다.

## §3 이 단계에서 정하는 정책 (PO)  {#s3-policies}

컨셉이 M-002 로 넘긴 네 건이다.

### §3.1 PO-1 정정 경로 (O14)  {#s3-1-correction}

> **원 답변을 수정하고, 정정했다는 사실을 본문에 명시한다.**

| 후보 | 판단 |
|---|---|
| 수정만 하고 조용히 넘어간다 | **아니다.** 이미 읽은 사람이 잘못된 내용을 그대로 갖고 간다 |
| 후속 답글로만 정정 | 원 답변이 틀린 채 남아, 나중에 읽는 사람이 정정을 놓친다 |
| **원 답변 수정 + 정정 명시** | **채택.** 나중에 읽는 사람은 바른 내용을, 이미 읽은 사람은 변경 사실을 본다 |

정정 시 **무엇이 왜 바뀌었는지**를 함께 적는다. 근거 버전 고정(D20)이 있으므로
"어느 근거가 stale 되어 고쳤는지"를 기계가 채울 수 있다.

- **검증**: 코드 커밋으로 지식 항목이 stale 되면, 그 근거를 쓴 게재 답변이 Q5 에 뜨고,
  정정 후 원 답변에 정정 표시가 남는다.

### §3.2 PO-2 봇 답변자 표기 (O15)  {#s3-2-attribution}

> **AI 가 작성했음을 답변에 명시한다.** 근거 목록을 함께 싣는다.

숨기지 않는 이유는 넷이다.

1. 근거 목록을 함께 보여주므로 **AI 산출임이 어차피 드러난다**
2. 숨겼다가 오답이 문제가 되면 **신뢰 타격이 훨씬 크다**
3. 사내 시스템이라 투명성의 비용이 낮다
4. **콘텐츠에는 이미 귀속 표시를 요구했다**(§7.6.5). 답변만 숨기면 일관성이 깨진다

- **검증**: 게재된 답변에 작성 주체와 근거가 표시된다.

### §3.3 PO-3 개인정보 취급 범위 (O6)  {#s3-3-pii-scope}

이용자는 사내 인증으로 식별되므로(D13) QnA 기록에 질문자 식별자가 붙는다.

> **지식 항목에는 질문자 식별자를 남기지 않는다.** 종결 기록의 첫 필드가
> *일반화된 질문*인 것(§6.5.2)이 이 요구를 이미 담고 있다 — 개인·상황 특정 요소를
> 걷어낸 형태여야 한다.

| 저장소 | 질문자 식별자 |
|---|---|
| QnA 기록 · 티켓 (운영 DB) | **보관** — 추적과 통계에 필요하다 |
| 지식베이스 (파일) | **보관하지 않는다** |
| 답변 이력 | 보관 (게재 대상 추적) |
| 콘텐츠 | **보관하지 않는다** — 대외 노출물이다 |

지식베이스가 OKF 번들로 내보내질 수 있다는 점(§3)이 이 구분을 특히 중요하게 만든다.

- **검증**: 지식 항목과 콘텐츠에서 개인 식별자를 검색해 0건.

### §3.4 PO-4 보존 기간 (O45)  {#s3-4-retention}

전건 티켓 발행(D19)이므로 기록이 무한정 쌓인다.

> **원칙**: 지식은 남기고 **원본은 만료**시킨다. Raw Layer 의 QnA 원문과 티켓은
> 보존 기간을 두되, 그로부터 승격된 **지식 항목은 만료되지 않는다** — 이미 개인 식별
> 요소가 없기 때문이다(PO-3).

**확인 결과(2026-08-28): 사내에 정해진 보존 정책이 없다.** 따라서 **기본값은 무기한
보관**이 된다.

> **다만 이것을 "정책 부재"가 아니라 **결정**으로 기록한다.** 정책이 없어서 그냥
> 쌓이는 것과, 두지 않기로 정한 것은 나중에 달라진다 — 전자는 개인정보 이슈가
> 생겼을 때 소급이 어렵다.

**만료 기능 자체는 설계에 포함한다** (PO-4-a). 기간을 **설정값으로 두고 기본을
무제한**으로 하면, 나중에 정책이 생겨도 값만 넣으면 된다. 지금 만들지 않으면
그때 만들어야 하고 그 사이 쌓인 것은 그대로 남는다.

위험이 크지 않은 이유는 **PO-3 가 이미 대부분을 막고 있기** 때문이다 — 지식 항목과
콘텐츠에는 식별자가 없고, 쌓이는 것은 QnA 원문·티켓·답변 이력뿐이다.

- **검증**: 보존 기간 설정이 존재하고 기본값이 무제한이다. 값을 넣으면 그 기간이 지난
  QnA 원문이 삭제되며, 그로부터 승격된 지식 항목과 통계 집계값은 남는다.

## §4 기능 요구사항 (FR)  {#s4-functional}

단계별로 묶는다. **앞 단계의 대기열이 밀려 있으면 다음 단계를 켜지 않는다**(D51).

### §4.1 S0 — 수집과 지식베이스 구축  {#s4-1-s0}

| ID | 요구 | 검증 | 근거 |
|---|---|---|---|
| **FR-1** | 모 시스템 소스 저장소의 **코드와 히스토리(커밋 메시지·PR 설명)** 를 수집한다. 저장소는 **여럿일 수 있고**, 각자 미러와 커서를 갖되 **지식베이스는 하나다** (ADR-006 §multi-repo) | 저장소 스냅샷과 커밋 메타가 Raw Layer 에 적재된다. 저장소를 더해도 항목은 한 자리에 모인다 | D16 |
| **FR-2** | 변경을 감지해 **해당 범위만 증분 수집**한다. 최초 1회는 전체 | 새 커밋 유입 시 그 범위만 재수집된다 | §4 |
| **FR-3** | 에이전트가 원천을 읽어 **지식 항목을 생성·갱신**한다. 로컬 LLM 으로 수행한다 | 지식 항목이 생성되고 소스코드가 외부로 전송되지 않는다 | D5 |
| **FR-4** | 모든 지식 항목은 **출처(커밋 해시 / QnA ID)** 를 갖는다 | 출처 없는 항목 0건 | D3 |
| **FR-5** | 지식 항목을 **파일로 저장하고 git 으로 이력을 남긴다.** 커밋은 **묶음 단위**이고, 1 회 ingest 는 `log.md` 에 **한 줄**을 남긴다 (2026-09-03 개정 — 아래 주 참조) | 묶음마다 커밋이 생기고 커밋 메시지가 진행(`43/116`)을 담는다. 런 하나가 로그 한 줄을 남긴다 | D12, O30 |
| **FR-6** | 충돌 시 덮어쓰지 않고 **양쪽을 남기고 모순 표시**한다 | 기존 항목과 어긋나는 판단이 Q4 로 올라온다 | D38 |
| **FR-7** | **Lint** 를 주기 실행한다 — 모순 · stale · 고아 · 끊어진 링크 · 참조 부재 · **죽은 무효화**(조건이 나타날 수 없는 경로를 가리킨다) | 검사 결과가 대기열(Q4·Q5)로 이어진다 | §4 |
| **FR-8** | 출처 커밋이 낡으면 해당 지식 항목을 **stale 로 표시**한다 (삭제하지 않는다). 무효화 조건은 **변경분에 나타날 수 있는 경로**만 든다 — ingest 가 나머지를 떨어내고(대비값으로 간다), Lint 가 나중에 죽은 것을 잡는다 | 코드 변경 후 관련 항목에 stale 이 붙는다. 조건이 붙어 있는데 아무것도 가리키지 못하는 항목이 만들어지지 않는다 | §4 |
| **FR-9** | **설정값은 ingest 하지 않는다** — 집행 지점이 **둘**이다: 설정 **경로**를 원천에서 빼고, 원천이 선언한 **이름과 값을 한 줄에 나란히 적은 제안**을 받지 않는다 | 설정 파일의 값이 지식 항목으로 들어가지 않고, 코드 상수·커밋 메시지로 우회한 값도 걸린다 | D16 |
| **FR-52** | **QnA 이력을 수집한다** — 질문 · 답변 · 후속 답글 · 해결 표시. 답변에는 **작성자 계정**을, 해결에는 **등급**을 함께 보관한다 | Raw Layer 에서 봇/사람 답변이 구분되고 해결 등급이 남는다 | D2, D7, D8 |
| **FR-53** | **지식 항목을 언어별로 나누지 않는다.** 항목은 **원천의 언어를 따르며** 한 항목 안의 혼재를 허용한다 | 같은 개념에 대한 언어별 중복 항목이 없다 | D52, D54 |
| **FR-54** | 사람이 지식 항목을 **직접 편집**할 수 있다. 편집 시 **왜 고쳤는지 · 무효화 조건 갱신 · 사람이 고쳤다는 표시** 셋을 남긴다 | 세 가지 없이는 편집이 반영되지 않는다 | D37 |
| **FR-55** | 지식베이스를 **OKF 형식으로 유지**한다 — 1 파일 1 개념, `type` 을 포함한 frontmatter, 예약 파일(`index.md` · `log.md`). **내보내기 기능은 수요가 확인되면 만든다** | 지식 항목이 형식을 만족한다 | D4 |

> **FR-5 개정 (2026-09-03) — 커밋 단위를 런에서 묶음으로.** 원래 문구는 "1 회
> ingest = 1 커밋"이었고 근거는 llm-wiki 운영 모델(O30)이었다. 실측이 그 규칙의
> 대가를 드러냈다: 부트스트랩 한 번이 **4.96시간**인데 커밋이 끝에 한 번뿐이라,
> 그동안 지어진 항목은 디스크에만 있고 **게재가 근거를 고정하지 못한다**
> (FR-28 의 근거 버전 고정은 커밋을 요구한다). 즉 지식을 짓는 내내 답변이 하나도
> 나가지 못한다.
>
> **바뀐 것은 커밋의 단위이지 이력의 성격이 아니다.** "이 원천을 읽고 이만큼
> 알게 됐다"는 기록은 그대로이고 단위만 좁아졌으며, 근거 버전 고정 관점에서는
> **오히려 정밀해진다** — 답변이 더 좁은 시점에 묶인다. llm-wiki 가 말한 "1 커밋
> = 1 ingest"의 취지(무엇을 읽어 무엇이 바뀌었는가를 한 덩어리로 남긴다)는
> **`log.md` 의 한 줄**이 계속 진다.
>
> 대가는 중단된 런의 읽다 만 상태가 이력에 남는 것이고, 커밋 메시지의 진행
> 표시(`43/116`)가 그것을 완주와 구분한다.

| 3 | **XR-2 작성자 계정 노출** | **가능** | **대안 없던 유일한 항목이 풀렸다.** §5.3 되먹임 차단과 경로 B 가 성립한다 |

### §7.2 남은 확인  {#s7-2-remaining}

| # | 항목 | 상태 |

| 4 | **O41 커밋 위생** — 저장소 히스토리에 "왜"가 실제로 남아 있는가 | **보류.** FR-1(히스토리 수집)의 값이 여기 달렸으나, 운영자가 곧 커밋을 쓰는 사람이므로 고정 제약이 아니라 개선 가능한 변수다 (§8.6.2) |

### §8.1 요구사항이 되지 않은 결정  {#s8-1-not-requirements}

컨셉 결정 55개 중 **넷은 요구사항으로 번역되지 않는다.** 누락이 아니라 **성격이
다르기 때문**이며, 그 사실을 남겨 두어야 다음에 감사할 때 다시 찾지 않는다.

| 결정 | 왜 요구사항이 아닌가 |
|---|---|
| **D1** 본체는 지식베이스다 | 시스템의 **성격 선언**이다. 개별 요구사항이 아니라 §4 전체의 배열을 정한다 |
| **D29** 의견 금지의 이유는 귀속이다 | D28(의견 금지)의 **근거**다. 요구는 FR-40 이 담는다 |
| **D43** W4 의 실체는 기록의 부재다 | 문제의 **재정의**다. 대응은 D44 → FR-10 이 담는다 |
| **D45** 유인은 담당자 자신의 이익이다 | **설계 원칙**이다. FR-11(등록 부담 최소화)이 이 원칙을 따르지만 원칙 자체는 검증 대상이 아니다 |
