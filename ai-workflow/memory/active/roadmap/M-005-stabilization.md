# M-005 — 실데이터 연결과 운영 준비

구현은 닫혔다(M-004, 40 leaf). **한 번도 실제 모 시스템에 붙어 본 적이 없다는 것**이
남은 전부다. 이 마일스톤이 존재하는 이유는 그 사실 하나다.

지금까지의 검증은 **우리 저장소 둘과 mock QnA** 위에서 이뤄졌다. 소스 쪽
파이프라인은 실데이터(auto-trading 185항목)로 돌았고 답변 파이프라인도
실지식베이스·실모델로 끝까지 태웠지만, **유입은 여전히 mock 이다** — 질문이
모 시스템에서 오지 않는다.

## 이 마일스톤이 없으면 무슨 일이 생기는가

M-004 를 닫은 뒤 남은 일들이 **handoff 위험 목록에만 흩어져 있었다** — 대시보드
접근 제어 · `.env` 전환 · 임계값 일곱 · 미검증 축 셋. 전부 "실데이터가 오면"이라는
같은 전제를 공유하는데 아무도 소유하지 않아, 그날이 오면 **무엇부터 해야 하는지를
그때 다시 찾아야 했다.** 마일스톤 이름이 곧 그 전제다.

## 순서가 있다

**5.1 이 먼저다.** 나머지 넷이 전부 실데이터를 입력으로 받는다 — 임계값은 관측이
있어야 정해지고, 미검증 축은 실제 원천이 있어야 돌고, 접근 제어는 **게재가 실제로
나가기 시작하는 순간** 조건이 바뀐다.

**5.6·5.7 도 5.1 을 기다리지 않는다.** 5.7 은 오히려 5.1 이 없는 동안 더
쓸모가 있다 — QnA 유입이 mock 이라 **지식베이스가 무엇을 아는지 확인할 다른
경로가 없다.**

**5.6 도 5.1 을 기다리지 않는다.** 실데이터 없이 재고 고칠 수 있는 것이고,
모 시스템이 크면 부트스트랩이 하루를 넘기므로 **그날 게재가 멈춰 있으면 안 된다.**

**다만 5.2 는 5.1 과 같은 날 필요하다.** 실제 모 시스템을 붙이는 순간
대시보드의 POST 들(승인 · 게재 · 국면 전진)이 진짜 결과를 낳는다 — 지금은
S0 + mock 이라 나가지 않을 뿐이다.

## WBS

- **WBS-5.1** 실데이터 연결 — 산출물: 모 시스템 API 로 질문이 들어오고 답변이 나간다
  - **WBS-5.1.1** 모 시스템 어댑터 실연동 — 산출물: `ASD_PARENT_ADAPTER` 를 http 로, 여섯 읽기 표면과 게재 표면이 실제 API 를 친다 (XR-1~7, ADR-008)
  - **WBS-5.1.2** 실운영 설정 전환 — 산출물: `ASD_SIMULATED_SOURCE` 제거, `ASD_PARENT_REPO_URL` 을 실제 저장소로. **NFR-1 의 소스 조건이 풀린 채 원격 LLM 이 열리지 않는다**
  - **WBS-5.1.3** QnA 유입 실검증 — 산출물: 실제 질문이 수집 → 유입 → 파이프라인 → Q2 → 게재 → 종결 기록까지 한 줄로 도는 것을 확인한다
- **WBS-5.2** 접근 제어 — 산출물: 게재가 실제로 나가는 구성에서 화면이 아무나 누를 수 없다
  - **WBS-5.2.1** 위험 조합 기동 거부 — 산출물: 어댑터가 mock 이 아니거나 게재 단계(S3+)인데 시뮬레이션 선언이 켜져 있거나 화면이 루프백 밖에 인증 없이 열려 있으면 **기동하지 않는다** (ADR-010 과 같은 형태)
  - **WBS-5.2.2** 대시보드 인증 — 산출물: 사내 단일 운영자용 최소 인증. 최종 이용자 인증은 범위 밖(모 시스템 책임)이라 **이 화면 자체의 접근 제어**만 정한다
- **WBS-5.3** 임계값 확정 — 산출물: 지어낸 값이 관측된 값으로 바뀐다
  - **WBS-5.3.1** 국면 전진 임계 — 산출물: `operations/phase_thresholds.toml` 을 채운다. **지금 비어 있어 전진이 영영 제안되지 않는다** (O8)
  - **WBS-5.3.2** 나머지 여섯 — 산출물: `ASD_QUIET_HOURS`(336h) · 재검증 3건/7일(O50) · 알림 3일(O53) · `CONFIRMED_COVERAGE` · 군집 유사도 0.6(O37) · 보존 기간. 전부 설정·선언 파일에 있고 코드에는 없다
- **WBS-5.4** 미검증 축 — 산출물: 라이브에서 한 번도 돌지 않은 세 축이 돈다
  - **WBS-5.4.1** 임베딩 다리 — 산출물: O57(레이트 리밋)을 넘어 실제로 색인이 서고 검색에 기여한다. **지금은 벡터 차원조차 확인되지 않았다**
  - **WBS-5.4.2** 주기형 무효화 — 산출물: `periodic` 항목의 stale 판정이 실제로 발동한다
  - **WBS-5.4.3** 두 저장소 동시 완주 — 산출물: 코드 경로는 `test_multi_source.py` 가 덮지만 실저장소로는 재지 않았다
- **WBS-5.6** 갱신과 질의의 공존 — 산출물: 지식베이스를 짓는 동안에도 답변이 나간다
  - **WBS-5.6.1** 묶음 단위 커밋과 원자적 쓰기 — 산출물: 디스크와 커밋의 어긋남이 최대 한 묶음이 되어 긴 런 중에도 `pin()` 이 성립한다. 파일 쓰기는 tmp + `os.replace` 로 부분 읽기를 없앤다
- **WBS-5.7** 지식베이스 질의 콘솔 — 산출물: 운영자가 지식이 무엇을 아는지 직접 확인한다
  - **WBS-5.7.1** `/ask` 화면 — 산출물: 질문 하나를 답변 파이프라인 1~3단계에 태워 근거·강도·경계·멈춘 이유를 보여 준다. **아무것도 저장하지 않는다** (FR-60, §8.1)
  - **WBS-5.7.2** 대상별 정제 — 산출물: 같은 초안을 고객응대용·개발자용 두 글로 다시 쓴다. **파이프라인을 건드리지 않고**(게재되는 글의 모양이 바뀌면 안 된다) **새 사실을 더하지 않는다** (FR-61)
- **WBS-5.5** 운영 진입 판정 — 산출물: S0 에서 다음 단계로 올려도 되는지 근거로 답한다
  - **WBS-5.5.1** 단계 상향 조건 확인 — 산출물: §1.5.4 의 "앞 단계 대기열이 밀려 있으면 다음을 켜지 않는다"를 실제 대기열 수치로 판정한다
  - **WBS-5.5.2** 자동 승격 전제 확인 — 산출물: 국면을 2 로 올리기 전에 표본 재검증(WBS-4.8.4)이 실제로 도는 것을 확인한다 (§6.8.4-a)

## 완료 조건

1. 실제 모 시스템 질문 하나가 **수집부터 종결 기록까지** 사람 손을 거쳐 끝까지 간다
2. 게재가 나가는 구성에서 **인증 없는 화면으로는 기동하지 않는다**
3. 임계값 일곱이 **관측에 근거한 값**으로 채워진다 (비워 두기로 한 것은 그 이유를 적는다)
4. 미검증 축 셋이 각각 **한 번은 실제로 돈다**

## 위험

- **실데이터가 언제 오는지는 우리가 정하지 못한다.** 모 시스템 API 접근이 전제라
  5.1·5.3·5.4 는 그날까지 시작되지 않는다. 그동안 할 수 있는 것은 **그날의 조건을
  코드로 굳혀 두는 것**뿐이고, 그것이 5.2.1 이다 — 이 마일스톤이 `in_progress` 인
  이유가 그 하나다.
- **임계값을 지어내 좁히면 1국면의 정상이 경보로 바뀐다.** 기본값이 전부 넉넉한
  쪽인 것은 그 때문이다 — 관측 없이 조이지 않는다.
