## 1. Goals

이 프로젝트가 도달하려는 목표.

- **G1**: 사내 서비스 데스크로 들어오는 요청을 AI agent 가 *분류 → 정보 수집 → 해결 또는 에스컬레이션* 까지 자율적으로 처리하는 시스템을 만든다
- **G2**: agent 가 조직의 지식(런북·FAQ·과거 티켓)에 근거해 답하도록 하여, *근거 없는 답변* 대신 *출처가 붙은 답변* 을 기본값으로 만든다
- **G3**: 사람이 반드시 개입해야 하는 경계(권한 변경, 비용 발생, 되돌릴 수 없는 조치)를 명시적으로 정의하고, 그 경계를 agent 가 넘지 않도록 강제한다
- **G4**: 처리율·정확도·에스컬레이션 비율을 측정 가능한 지표로 남겨, 운영 중 agent 품질 저하를 조기에 감지한다

## 2. Key Questions

이 저장소가 답하려는 핵심 질문:

- **Q1**: 어떤 유형의 요청이 agent 로 *완결 가능* 하고, 어떤 유형이 *반드시 사람* 을 거쳐야 하는가 — 그 경계를 무엇으로 판정하는가?
- **Q2**: agent 가 조직 지식에 *근거* 해 답한다는 것을 어떻게 *검증* 하는가 (출처 추적, 환각 탐지, 오답 회수)?
- **Q3**: 요청자·상담원·운영자 각각에게 agent 의 판단 근거를 *어떤 형태로* 노출해야 신뢰가 유지되는가?
- **Q4**: 기존 티켓 시스템·인증·알림 채널과 어떤 계약(API/이벤트)으로 연결해야 교체 가능한 구조가 되는가?
- **Q5**: 운영 중 품질 저하(지식 노후화, 모델 변경, 신규 요청 유형)를 어떤 신호로 감지하고 어떻게 되돌리는가?

## 3. Research Scope

### 포함 영역

- 요청 인입 → 분류 → 응답/조치 → 종결 에 이르는 서비스 데스크 워크플로우 설계
- agent 오케스트레이션 (도구 정의, 다단계 처리, 사람 개입 지점)
- 조직 지식 검색·근거 제시 (런북 / FAQ / 과거 티켓 기반 RAG)
- 에스컬레이션 정책과 권한 경계 정의
- 티켓 시스템 · 인증 · 알림 채널 연동 계약
- 평가 체계 (정확도, 처리율, 에스컬레이션 비율) 와 회귀 감지
- 대화 로그 · 개인정보 취급 정책

### 제외 영역

- LLM 모델 자체의 fine-tuning / 학습 파이프라인
- 인프라 IaC (Terraform / CDK) 자동화 — 별도 저장소에서 다룬다
- 티켓 시스템 자체의 대체 구현 — 기존 시스템에 *연동* 하되 재구현하지 않는다
- 서비스 데스크 범위를 벗어난 일반 사내 업무 자동화 (인사·회계 프로세스 등)
- 고객 대면(B2C) 상담 채널 — 1차 대상은 사내 요청으로 한정한다

## 4. Evolving Thesis

*현재까지의 working hypothesis* (시간에 따라 변한다):

- 서비스 데스크 요청의 다수는 *지식 조회형* 이며, 이 구간을 agent 가 근거 있는 답변으로 처리하는 것만으로도 유의미한 효과가 난다 — 자동 *조치* 는 그 다음 단계다
- agent 의 신뢰는 정확도보다 *경계의 예측 가능성* 에서 나온다. "무엇을 하지 않는지" 가 명확한 agent 가 더 넓게 채택된다
- 사람 개입은 실패 처리가 아니라 *설계된 경로* 다. 에스컬레이션 품질이 곧 시스템 품질이다
- 지식 베이스의 노후화가 agent 품질 저하의 1차 원인일 가능성이 높다 — 모델 교체보다 지식 갱신 루프가 더 중요하다
- 티켓 시스템·채널은 교체될 수 있는 외부 의존이며, 도메인 로직과 어댑터를 분리해 두어야 한다
