| ~~**O30**~~ | ~~지식베이스의 버전 관리를 git 으로 할 것인가~~ | **닫힘 (최종 리뷰)** — **git 이다.** §3 이 차용한 llm-wiki 운영 모델이 이미 "1 커밋 = 1 ingest"·`log.md` append·additive merge 를 전제하므로(D4), 파일 저장 확정(§9.4)과 합쳐지면 선택지가 남지 않는다. O46(버전 단위)은 커밋 해시로 귀결된다 |

| ~~**O38**~~ | ~~기능 도입 순서~~ | **닫힘 (라운드 26)** — **여섯 단계 S0~S5**. S0~S2 는 대외 노출이 없고, 가이드가 FAQ 보다 먼저 온다. 진입 조건에 운영자 부하가 포함된다 (§1.5) |
| ~~**O39**~~ | ~~티켓의 구체적 상태 집합~~ | **닫힘 (라운드 20)** — **자동종결 / 열림 / 진행중 / 보류 / 종결** 다섯. 배정·우선순위·마감·이관 필드 없음. 진행중·보류는 인원이 아니라 **겸업이라 접속이 띄엄띄엄해서** 필요하다 (§6.7) |
